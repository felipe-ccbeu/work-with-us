PARTE 01

Sistema: onde hospedar e onde guardar

A pesquisa começou procurando o melhor par gratuito de hospedagem e banco. Encontrou primeiro um problema jurídico que elimina a opção mais óbvia.

Achado crítico

O plano gratuito da Vercel proíbe uso comercial — e a definição pega o nosso caso

A Vercel é o destino natural de qualquer projeto Next.js, e o plano Hobby é gratuito. Só que a documentação oficial diz, com todas as letras:

Hobby teams are restricted to non-commercial personal use only. All commercial usage of the platform requires either a Pro or Enterprise plan.Vercel — Fair Use Guidelines, atualizado em 29/07/2026

O detalhe que fecha a porta é como eles definem “uso comercial”: qualquer deploy usado para ganho financeiro de qualquer pessoa envolvida em qualquer parte da produção do projeto — e a lista de exemplos cita explicitamente “a paid employee or consultant writing the code”.

Uma página de carreiras de uma empresa, escrita por um funcionário pago, cai exatamente nessa descrição. O caminho legítimo dentro da Vercel é o plano Pro, a US$ 20/mês.

Traduzindo: isso é regra de verdade ou letra morta?

É regra de contrato, aplicada de forma desigual. Muita gente roda site comercial no Hobby e nunca é incomodada. Mas a Vercel pode pausar a conta sem aviso, e quem sofre o prejuízo é a empresa, não a plataforma.

Para um projeto interno de fim de semana, o risco é aceitável. Para a página onde os candidatos da empresa se inscrevem — a porta de entrada pública do RH — ficar fora do ar por violação de termos é um custo que não vale os US$ 20 economizados. Por isso a pesquisa procurou alternativa em vez de ignorar a cláusula.

As alternativas permitem uso comercial no plano gratuito

Cloudflare e Netlify não têm essa restrição. As duas declaram uso comercial permitido no tier gratuito.

Traduzindo: o que é OpenNext?

O Next.js foi feito pela Vercel e roda melhor lá. O OpenNext é um projeto que traduz uma aplicação Next.js para rodar em outras infraestruturas — Cloudflare, AWS, Netlify.

O adapter da Cloudflare é oficial e mantido por eles, e roda o Next.js no modo Node.js, não no modo Edge. Isso importa porque o modo Edge derruba boa parte das bibliotecas de Node. Ainda existem limitações em recursos de cache mais avançados, mas nada que um formulário de candidaturas use.

Escolha recomendada

Supabase, por um motivo específico

O Neon é o melhor banco puro da lista. Mas o Supabase é o único que resolve os três problemas do projeto de uma vez só: Postgres para as candidaturas, Storage para os PDFs de currículo, e autenticação para o painel do RH.

Escolher o Neon significaria contratar mais dois serviços separados e costurar tudo. Para um projeto que precisa sair do papel, isso é atrito sem retorno.

Ponto de atenção

O Supabase gratuito pausa o projeto depois de 7 dias parado

Página de carreiras tem exatamente esse perfil: fica semanas sem ninguém acessar, e aí abre uma vaga e o tráfego chega de uma vez. Se o projeto estiver pausado, a primeira pessoa a se candidatar encontra o site fora do ar.

Duas saídas, ambas baratas: agendar um acesso automático a cada poucos dias para manter o projeto acordado, ou aceitar que a primeira visita da semana demore alguns segundos a mais.

Dois complementos gratuitos que a comunidade sempre acopla

  • Cloudflare Turnstile — bloqueio de robôs sem aquele quebra-cabeça de identificar semáforos. É gratuito e praticamente obrigatório: formulário público sem proteção vira alvo de spam em questão de dias.
  • Resend — envio do e-mail de confirmação para o candidato. O plano gratuito cobre com folga o volume de uma página de carreiras, e a configuração de domínio é simples, o que evita que a confirmação caia no spam.

PARTE 02

Formulários: o que a comunidade usa

Aqui há consenso raro. A combinação padrão está estabelecida há anos e não há motivo neste projeto para fugir dela.

12 midownloads por semana do React Hook Form — é o padrão de fato
1 MBlimite padrão de envio do Next.js — um PDF de currículo estoura
51%das home pages da web têm campo de formulário sem rótulo

React Hook Form + Zod

O React Hook Form trabalha com campos não controlados: em vez de o React reprocessar o formulário inteiro a cada tecla digitada, cada campo cuida de si. Num formulário longo como o de candidatura, isso é a diferença entre digitação fluida e digitação travada.

O Zod entra como o verificador das regras. A vantagem que o consagrou é que uma única declaração serve para duas coisas ao mesmo tempo: a validação e o tipo TypeScript. E a mesma regra roda no navegador e no servidor, sem escrever duas vezes.

Traduzindo: por que validar duas vezes, no navegador e no servidor?

A validação no navegador existe para o usuário: avisa na hora que o e-mail está errado, sem precisar recarregar a página. É conveniência.

A validação no servidor existe para o sistema: qualquer pessoa com um pouco de conhecimento consegue enviar dados direto, pulando a tela. É a única que realmente protege o banco. Ter as duas escritas na mesma declaração significa que elas nunca vão discordar entre si — que é o bug clássico dessa dupla.

Quando valeria escolher outra coisa

  • TanStack Form — se o formulário tivesse campos que se multiplicam e se aninham dinamicamente, com exigência de tipagem muito estrita.
  • Conform — se funcionar com o JavaScript desligado fosse um requisito de arquitetura.

Nenhum dos dois casos é o nosso. React Hook Form + Zod é a escolha certa aqui, e o shadcn/ui já tem a integração documentada, o que economiza a parte chata da montagem visual.

Formulário em etapas

O React Hook Form não traz solução pronta para guardar o que foi preenchido enquanto o candidato navega entre etapas. A receita que a comunidade convergiu é acrescentar o Zustand para segurar esse estado, com uma regra de validação por etapa, conferida no momento de avançar — nunca só no final.

Armadilha técnica

O upload do currículo não pode passar pelo servidor

As Server Actions do Next.js aceitam, por padrão, 1 MB por envio. Currículo em PDF passa disso com facilidade — e o erro aparece só em produção, quando um candidato real tenta enviar.

A solução consagrada é a URL assinada. Vale desenhar assim desde o começo: reescrever depois custa mais do que fazer certo agora.

Traduzindo: o que é uma URL assinada?

Em vez de o arquivo subir para o nosso servidor e de lá para o armazenamento, o servidor apenas emite um crachá temporário: um endereço secreto, válido por poucos minutos, que autoriza um único envio.

O navegador do candidato usa esse endereço para mandar o PDF direto ao armazenamento. O arquivo nunca passa pelo nosso servidor — o limite de 1 MB deixa de existir, e o gasto de processamento também.

O mesmo mecanismo funciona na volta: quando alguém do RH vai ler um currículo, o sistema gera um endereço temporário para aquele arquivo. Ninguém consegue adivinhar o link de um currículo alheio, e o endereço expira sozinho.

Acessibilidade não é enfeite neste projeto

O relatório WebAIM Million de 2026 aponta campo de formulário sem rótulo como a terceira falha de acessibilidade mais comum da web, presente em 51% das home pages analisadas.

Num formulário de candidatura, essa falha tem um nome específico: é excluir uma pessoa com deficiência do processo seletivo por causa do código. É problema de produto e é exposição jurídica.

O mínimo, seguindo a norma WCAG 2.2 nível AA:

  • Rótulo de verdade, visível, ligado ao campo. Texto cinza dentro da caixa não é rótulo: some quando a pessoa começa a digitar e leitores de tela nem sempre o anunciam.
  • Marcar o tipo de cada campo pessoal com o atributo autocomplete. O navegador passa a preencher sozinho. Para quem tem dislexia ou mobilidade reduzida nas mãos, isso não é comodidade — é o que torna o formulário utilizável.
  • Erro escrito, dizendo qual campo e como consertar. Borda vermelha sozinha não comunica nada para quem não enxerga, e “campo inválido” não ajuda ninguém.
  • Erro ligado ao campo por aria-describedby, que é o mecanismo com melhor suporte nos leitores de tela hoje.
  • Validar quando a pessoa termina o campo, não a cada tecla. Acusar erro no meio da digitação do e-mail é irritante e não ajuda.
  • Tudo navegável só pelo teclado, com indicação visível de onde está o foco.

Nada disso é caridade: segundo o Nielsen Norman Group, formulários que seguem boas práticas de usabilidade quase dobram a taxa de conclusão na primeira tentativa.

RH profissional: o que perguntar

Esta parte é para ler junto com quem cuida do RH. As decisões aqui valem mais para o resultado do que qualquer escolha técnica das partes anteriores.

O número que manda em todo o resto

12,47%dos candidatos concluem quando o formulário leva menos de 5 minutos
3,61%concluem quando o formulário passa de 15 minutos
+245%de aumento na conclusão ao encurtar para menos de 5 minutos

A regra prática que circula entre recrutadores é direta: se o formulário não termina em duas roladas de polegar no celular, está longo demais.

A consequência para o desenho: cada campo precisa justificar por que existe. O teste é sempre o mesmo — essa resposta muda a decisão de triagem? Se não muda, o campo sai, vira opcional, ou é adiado para uma etapa posterior do processo.

Traduzindo: o que são perguntas eliminatórias (knockout questions)

São perguntas objetivas, de sim ou não, sobre requisitos inegociáveis da vaga. “Tem CNH categoria B?”, “Tem disponibilidade para viajar?”, “Tem registro ativo no conselho da profissão?”

São o maior ganho de informação por segundo gasto do candidato: em cinco segundos separam quem pode seguir de quem não pode, poupando o tempo dos dois lados.

O teste para saber se a pergunta merece estar lá: se a resposta “não” não elimina ninguém de fato, então não é pergunta eliminatória — é curiosidade. E curiosidade custa taxa de conclusão. Corte.

O que não pedir

  • Currículo e histórico profissional digitado à mão. É a redundância que mais faz candidato desistir no meio: ele já anexou tudo aquilo, e agora precisa digitar de novo. Escolha um dos dois.
  • CPF, RG, data de nascimento, estado civil, foto, nome dos pais, endereço completo. Nenhum desses muda a triagem. Todos aumentam o risco sob a LGPD e alguns são vetor clássico de discriminação. Peça na admissão, para quem foi contratado.
  • Laudo de PcD na inscrição. É dado de saúde, com proteção legal mais rígida. Se a empresa precisa dele para a Lei de Cotas, peça na etapa de admissão — não na porta de entrada.

Se a empresa optar por coletar autodeclaração de diversidade, a forma correta é: campo sempre opcional, com a opção “prefiro não informar”, finalidade explicada ao lado do campo, e resposta invisível para quem faz a triagem técnica.

Do outro lado: o painel de entrevistas

Este é o achado mais forte da pesquisa, e o que mais muda resultado de contratação.

0,20poder de previsão de entrevista sem roteiro nem nota — quase o mesmo que sortear
0,51com roteiro fixo e ficha de avaliação com níveis descritos
48%dos gestores de RH admitem que viés afeta suas decisões

Mais que o dobro de acerto, sem gastar um centavo — só mudando o método. E o detalhe que separa a ficha de avaliação boa da inútil não é a pergunta: é a descrição do que significa cada nota. É ela que faz dois entrevistadores diferentes darem a mesma nota para a mesma resposta.

O que o painel precisa ter, em ordem de valor:

  1. Ficha de avaliação estruturada. Competências tiradas da análise real da vaga, não de uma lista genérica de “boas perguntas de entrevista”. Nota de 1 a 5, com cada nível descrevendo o que se espera ver.
  2. As mesmas perguntas, na mesma ordem, para todo candidato. De 3 a 5 por competência. É o controle de viés mais barato que existe.
  3. Anotação de evidência, não de impressão. “Contou que reverteu o deploy em 4 minutos” serve; “pareceu proativo” não serve.
  4. Etapas visíveis — novo, triagem, entrevista, proposta, contratado ou recusado.
  5. Histórico de quem mudou o quê e quando, sem possibilidade de apagar.

LGPD: quatro obrigações que viram código

Currículo é dado pessoal. No instante em que a empresa recebe um, passa a ser responsável por ele perante a lei. Guardar currículo para sempre “por via das dúvidas” é exatamente o comportamento que a LGPD mira.

  1. Consentimento explícito, com prova. Caixa não pré-marcada — caixa já marcada não é manifestação de vontade. E é preciso registrar data, hora, versão do texto aceito e IP: sem esse registro, a empresa não consegue provar que houve consentimento.
  2. Finalidade declarada e limitada. Os dados servem para avaliar aquela candidatura. Usar para qualquer outra coisa exige nova autorização.
  3. Prazo de descarte declarado e automático. A prática de mercado é de 6 meses a 1 ano, com renovação do consentimento ao fim. No sistema isso vira uma rotina agendada que apaga o registro e o arquivo do currículo — apagar só a linha do banco e deixar o PDF no armazenamento é o erro mais comum.
  4. Banco de talentos é um segundo consentimento. Guardar o currículo depois do fim do processo é outra finalidade, e precisa de caixa própria, independente da primeira. Sem ela, a resposta certa é apagar.

Do lado da segurança, o mínimo: currículo nunca em pasta pública, painel do RH sempre atrás de login, e nenhum dado pessoal em log — e-mail, telefone e CPF não vão para registro de erro nem para ferramenta de monitoramento.

PARTE 04

A decisão que destrava o resto

Tudo acima converge para uma única escolha pendente.

Recomendação

Next.js + Supabase + Cloudflare, com Turnstile e Resend

Formulário em React Hook Form + Zod, três etapas, upload por URL assinada. Supabase cuidando de banco, arquivos e login do RH. Cloudflare hospedando via OpenNext. Turnstile barrando robôs, Resend confirmando a inscrição por e-mail.

Custo mensal: R$ 0, sem violar os termos de nenhum fornecedor. O único ponto a administrar é a pausa de 7 dias do Supabase.

A alternativa legítima é ficar na Vercel e assinar o plano Pro por US$ 20/mês. Compra o melhor suporte a Next.js que existe e elimina o trabalho de adaptação — é uma escolha válida, só não é gratuita.
